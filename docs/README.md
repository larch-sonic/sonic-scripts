# Larch Platform Patch — Build Flow

This document describes the end-to-end workflow for adding a new Larch platform
to a community SONiC build: patching, committing, and producing a final image.

---

## Overview

```
HardenedSonic/sonic-buildimage   (source: Marvell-specific platform files)
         │
         │  larch_add_platform_patch.sh
         ▼
dest/sonic-buildimage            (community SONiC repo, used as build workspace)
  ├── device/larch/<DEVICE>/     ← copied from HardenedSonic
  ├── platform/<PLATFORM>/       ← copied from HardenedSonic
  │   └── sai.mk                 ← overwritten: build-from-source → download prebuilt .deb
  └── <patch>.patch              ← generated by git format-patch
         │
         │  files/202511/        (patch + series file updated automatically)
         │
         │  sonic_build_script.sh
         ▼
target/sonic-marvell-teralynx.bin
```

---

## Step 1 — Create the platform patch

Run `larch_add_platform_patch.sh` once per new platform. It:

1. Copies `device/larch/<DEVICE>/` and `platform/<PLATFORM>/` from HardenedSonic
2. Rewrites `platform/<PLATFORM>/sai.mk` to download the prebuilt SAI `.deb` from
   `sonic-larch-binaries` instead of building from source
3. Commits those changes in the destination git repo
4. Runs `git format-patch` and saves the `.patch` to `files/202511/`
5. Appends the patch entry to `series_<PLATFORM>_<ARCH>`

### Usage

```bash
./larch_add_platform_patch.sh \
  --device   <device_dir>     \   # e.g. arm64-larch_canisminor
  --platform <platform_dir>   \   # e.g. marvell-teralynx
  --arch     <arch>           \   # e.g. amd64 or arm64
  --dest     <path/to/dest/sonic-buildimage> \
  --sai-version <version>         # e.g. 6.2.1 (teralynx) or 1.17.4-2 (prestera)
```

| Argument | Required | Description |
|---|---|---|
| `--device / -d` | yes | Subdirectory name under `device/larch/` |
| `--platform / -p` | yes | Subdirectory name under `platform/` |
| `--arch / -a` | yes | CPU architecture token used in the series filename |
| `--dest` | yes | Path to the destination community sonic-buildimage (must be a git repo) |
| `--sai-version / -s` | yes | Version string embedded into the generated `sai.mk` |
| `--src` | no | Source sonic-buildimage (default: `../../HardenedSonic/sonic-buildimage`) |
| `--series-dir` | no | Where patches and series files live (default: `<script_dir>/files/202511`) |
| `--commit-msg / -m` | no | Override the auto-generated git commit message |

### Example

```bash
./larch_add_platform_patch.sh \
  -d arm64-larch_canisminor \
  -p marvell-teralynx \
  -a amd64 \
  --dest ~/ComSonic/sonic-scripts/ABT-202511-25-05-2026_08-20-.../sonic-buildimage \
  --sai-version 6.2.1
```

After this step `files/202511/` contains the new `.patch` and the series file is updated.

---

## Step 2 — Build the SONiC image

Run `sonic_build_script.sh` to clone community SONiC at the required commit,
apply all patches (including the one just created), and compile the image.

```bash
./sonic_build_script.sh \
  -b 202511 \
  -p marvell-teralynx \
  -a amd64 \
  -c d7aa7e9c120ff00d9838f9f3b706bee3b1bbe2bb \
  --no-cache \
  --patch_script /home/bbryk/ComSonic/sonic-scripts/larch_sonic_patch_script.sh \
  --other_build_options "SONIC_BUILD_JOBS=20"
```

### Argument breakdown

| Argument | Value in example | Description |
|---|---|---|
| `-b 202511` | `202511` | SONiC branch to clone |
| `-p marvell-teralynx` | `marvell-teralynx` | Target platform / ASIC |
| `-a amd64` | `amd64` | CPU architecture of the build host and image |
| `-c <commit>` | `d7aa7e9c...` | Pin the community SONiC repo to this exact commit for reproducibility |
| `--no-cache` | — | Disable build cache; forces a clean rebuild of all Docker layers |
| `--patch_script <path>` | local path | Script that fetches and applies the series patches to the cloned repo. Can be a local path or an HTTP URL |
| `--other_build_options` | `SONIC_BUILD_JOBS=20` | Extra `make` variables passed straight to the SONiC build system. `SONIC_BUILD_JOBS` controls parallelism |

### What the patch script does

`larch_sonic_patch_script.sh` is called automatically by `sonic_build_script.sh`
inside the freshly cloned workspace. It:

1. Reads `series_<PLATFORM>_<ARCH>` to find all patches for the target platform
2. Downloads (or copies from a local path) each `.patch` file listed in the series
3. Applies them with `git am --3way`

The series file format is:
```
<patch-filename>|<target-repo>
```
e.g. `0001-Add-Larch-arm64-larch_canisminor-platform-files.patch|sonic-buildimage`

---

## Output

A successful build produces the image at:
```
<workspace>/sonic-buildimage/target/sonic-marvell-teralynx.bin
```

The workspace folder is named automatically using the build timestamp and commit:
```
ABT-202511-<DD-MM-YYYY>_<HH-MM>-<commit>/
```
